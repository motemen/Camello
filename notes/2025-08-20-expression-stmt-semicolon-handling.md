# `expression_stmt`におけるセミコロンの扱いに関する修正方針

## 1. 問題点

現状のパーサーの `expression_stmt` の実装では、式の後のセミコロンがオプション扱いになっている。

```rust
// expression_stmt の抜粋
// ... expressionのパース ...
if self.at(SyntaxKind::SEMICOLON) {
    self.bump();
}
```

これにより、`foo() bar()` のように、本来はセミコロンで区切られるべき複数の文が連続しているコードが、構文エラーとして検出されずに、それぞれが独立した文として解釈されてしまう。

## 2. 修正方針

`expression_stmt` は、原則として末尾にセミコロンを必須とするように変更する。

ただし、Perlの一般的な構文規則に従い、ブロック `{ ... }` の最後の文に限っては、セミコロンの省略を許容する。

## 3. 実装案

`expression_stmt` 関数を以下のように修正する。

1. 式（`self.expression()`）のパースを行う。
2. パース後、次のトークンをチェックする。
   - 次のトークンが **`SEMICOLON`** の場合：
     - 正常なケース。セミコロンを消費してパースを完了する。
   - 次のトークンが **`R_BRACE`** （閉じ波括弧 `}`）の場合：
     - ブロックの最後の文とみなし、セミコロンがなくても正常ケースとして扱う。セミコロンは消費しない。
   - 上記以外のトークンが続く場合：
     - 構文エラー。「`;` が必要です」といったエラーを報告する。

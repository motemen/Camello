| P0-1 | 済 | コメントを含むグループは flat にしない。加えてレンダラが行末コメントの後ろに書き込むことを構造的に拒否する |
| P0-2 | 済 | (a) DELIMITER をトークン単位で tight に (c) ERROR ノードは verbatim 出力 (d) 誤パース2経路とも根治 |

P0-2 の誤パースは2つとも字句解析の問題だった。
`use Module VERSION LIST` のバージョンをリストの先頭要素として読んでいたこと、
quote-like キーワードの後ろの `,` を区切りと見ていたこと
（perl に該当する例外はなく、`(q, 1)` は "can't find string terminator" で落ちる）。
経路2の `any { } qw(...)` は、prototype の見えない list operator にブロックを
渡す形で、**どちらの読みがパースできるか**で決着させた
（式の直後に項は来られないので、来たならハッシュの読みが誤り）。

## 5. レビューに載っていなかったが、ゲートが出したもの

すべて実コーパスの意味変化として現れた。

- `defined && -d` が `defined(&&-d)` になっていた。`&` はシグルで `&` は
  句読点変数の集合にあるので、`&&` が項位置でコード変数として字句解析されていた。
  `&&` という変数も `**` というグロブも存在しない。
- `print STDERR ("x")` が `STDERR` という名前の関数呼び出しとして読まれていた。
  perl は記号表で決めており camello にはそれがないので、全大文字の裸語 + `(` は
  本質的に曖昧だが、perl 自身のハンドルだけは常にハンドルである。
- `require v5.26` が `v5 . 26` になっていた。`name` は `take_name` 経由で
  識別子スキャナに読み直させるが、バージョンは名前ではない。
- `eval <<EOT; die $@ if $@;` の `die` が独立行に置かれ、
  heredoc 本体の1行目になっていた（本体はマーカーの**行**の次の行から始まる）。
- 同じ理由で、`sub f { return <<'EOT' }` の後に BLANK_LINE-1 が入れる空行が
  文字列の中に落ち、パスごとに1行ずつ増えていた。
- 直前の文の行末コメントが、後続する裸ブロックのブレースのものとして
  主張されていた。文境界を越えてコメントが動き、二重に出力されていた。
- POD / `__DATA__` の直前に書かれたコメントが出力から消えていた。
  これらのノードはコメントを出すトークン経路を通らない。P2-2 の不変条件が炙り出した。
